Ya sabemos que [los modelos pueden solicitar herramientas](/es/courses/llm-101/what-is-a-tool) y que AI Chat puede ayudarnos a [crear y modificar contenido interactivo](/es/courses/deepseek-101/ai-chat-tips).

Estas son funciones de los productos Chat. Entonces, ¿qué es un Agent, esa idea tan popular ahora? ¿En qué se diferencia de Chat?

## 1. ¿Qué es un Agent?

Un <JimmyNoteAnchor id="001">Agent</JimmyNoteAnchor> suele describirse como un agente inteligente o un representante.

<JimmyNote anchor="001">
    Hay muchas definiciones en el sector. Como el tema es complejo, esta lección se centra en el concepto principal. Trataremos los detalles en [Agent 101 (简体中文)](/zh/courses/agent-101).
</JimmyNote>

En las lecciones anteriores vimos que el modelo de Chat recibe la entrada del programa servidor, calcula y genera una respuesta. El servidor la devuelve al programa Chat, que te la muestra.

Un Agent funciona de forma algo distinta. Su programa pide primero al modelo que piense qué debe hacer. Después llama a una herramienta para actuar, observa el resultado y piensa en el siguiente paso.

Este ciclo de «pensar» → «actuar» → «observar» → «pensar» → «actuar» → «observar» se repite hasta completar la tarea.

## 2. ¿Cómo pasa el modelo de responder a pensar y actuar?

Veamos un ejemplo concreto para entender ese cambio.

Supongamos que el entrenamiento no contiene información sobre Inception ni The Matrix. El usuario pregunta: ¿cuánto suman el año de nacimiento del director de Inception y el año de estreno de la primera película de The Matrix?

El programa Agent envía un mensaje al programa servidor. Tras procesarlo, este devuelve datos con la siguiente estructura.

```json
{
  "messages": [
    {
      "role": "user", // Rol del mensaje: usuario
      "content": "¿Cuánto suman el año de nacimiento del director de Inception y el año de estreno de la primera película de The Matrix?" // Pregunta del usuario
    },
    {
      "role": "assistant", // Rol del mensaje: modelo
      "reasoning": "Para calcular la suma, necesito dos datos: el año de nacimiento del director de Inception y el año de estreno de la primera película de Matrix. Primero buscaré al director de Inception.", // Razonamiento del modelo
      "content": null, // Contenido generado: vacío. El modelo solicita una llamada a una herramienta en vez de responder.
      "tool_calls": [
        {
          "type": "function",
          "function": {
            "name": "search_web",
            "arguments": "{\"query\":\"Inception movie director\"}" // Buscar al director de Inception 
          }
        }
      ]
    },
    {
      "role": "tool", // Rol del mensaje: herramienta
      "content": "Inception es una película de acción y ciencia ficción estrenada en 2010, escrita y dirigida por Christopher Nolan." // Resultado devuelto por la herramienta
    }
  ]
}
```

Compáralo con el ejemplo anterior. Aparece un campo adicional, `reasoning`, que muestra el razonamiento del modelo. Es el paso de «pensar»:

```json
{
  "reasoning": "Para calcular la suma, necesito dos datos: el año de nacimiento del director de Inception y el año de estreno de la primera película de Matrix. Primero buscaré al director de Inception.", // Razonamiento del modelo
}
```

A partir de ese razonamiento, el modelo genera una solicitud para buscar al director de Inception. Es el paso de «actuar»:

```json
{
  "tool_calls": [
        {
          "type": "function",
          "function": {
            "name": "search_web",
            "arguments": "{\"query\":\"Inception movie director\"}" // Buscar al director de Inception 
          }
        }
      ]
}
```

La herramienta devuelve el resultado y el modelo pasa a «observar»:

```json
{
  {
    "role": "tool", // Rol del mensaje: herramienta
    "content": "Inception es una película de acción y ciencia ficción estrenada en 2010, escrita y dirigida por Christopher Nolan." // Resultado devuelto por la herramienta
  }
}
```



El JSON muestra que la herramienta devolvió el nombre del director, Christopher Nolan, pero no su año de nacimiento. El modelo vuelve a razonar y a llamar a una herramienta. Esta segunda ronda de pensar, actuar y observar produce lo siguiente:

## 3. ¿Por qué usar este patrón?

El ciclo repetido de «pensar» → «actuar» → «observar» también se llama [ReAct](https://react-lm.github.io/). Es el principio central de un Agent y su principal diferencia con AI Chat tradicional.

¿Por qué existe esta forma de trabajar?

En algunos casos, ejecutar AI Chat una sola vez no basta para que el modelo responda. En el ejemplo anterior, suponiendo aún que desconoce Inception y The Matrix, Chat podría dar esta <JimmyNoteAnchor id="002">respuesta</JimmyNoteAnchor>:

<Chat>
<ChatMessage from="user">
¿Cuánto suman el año de nacimiento del director de Inception y el año de estreno de la primera película de The Matrix?
</ChatMessage>

<ChatMessage from="assistant">
<ChatToolCall name="search_web" title="Buscar en la web" defaultOpen={true}>
**Argumentos de la llamada**

```json
{
  "query": "Inception movie director"
}
```

**Resultado devuelto**

```json
{
  "director": "Christopher Nolan"
}
```
</ChatToolCall>

Lo siento, solo sé que el director de Inception es Christopher Nolan. No conozco su año de nacimiento.
</ChatMessage>
</Chat>

<JimmyNote anchor="002">
    Quizá este ejemplo te parezca inadecuado: si los modelos han aprendido de tantos datos, ¿cómo no van a responder? En efecto, un producto Chat podría contestar bien esta pregunta concreta.
    
    Uso el ejemplo sobre todo para explicar el principio del Agent y mostrar cómo las herramientas y ReAct permiten resolver problemas desconocidos de forma autónoma. El entrenamiento suele llevar mucho tiempo, por lo que los conocimientos pueden ir varios meses, o incluso medio año, por detrás.
</JimmyNote>
