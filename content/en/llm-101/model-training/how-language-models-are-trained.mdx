We have seen how a model uses its input and parameters to calculate token probabilities. In this lesson, simple examples show how pretraining produces those parameters. You do not need to learn the training algorithms.

The process works roughly like this.

**Step 0: Initialize the parameters.**

We will continue using the earlier formula: `score = a × input + b`.

At the start of training, a and b have not yet been learned, so we assign initial values. Each candidate has its own a and b. For example, “umbrella” starts with a = 0.50 and b = 1.10. This step only initializes the parameters. It does not yet calculate scores or probabilities from an input.

**Step 1: Read some text and predict the next token.**

Using these initial parameters, the model reads a passage and predicts the next token. For example, the input is “It is raining today. Remember your…”.

In this simplified example, rain becomes the input x = 1. All three candidates use the same input, but their parameters differ, so their scores differ.

Softmax then converts the scores into probabilities that add up to 100%.

| Candidate | Score calculation | Score | Softmax probability |
| ---- | -------- | ---: | -----------: |
| umbrella | `0.50 × 1 + 1.10` | 1.60 | about 24.78% |
| raincoat | `1.00 × 1 + 1.08` | 2.08 | about 40.05% |
| hat | `0.80 × 1 + 1.15` | 1.95 | about 35.17% |

**Step 2: Check the correct answer.**

The model checks the original text in the training data: “It is raining today. Remember your umbrella”. The correct answer is “umbrella”.

**Step 3: Adjust the parameters.**

After seeing the correct answer, the model adjusts its parameters.

The earlier prediction gave “raincoat” the highest probability, about 40%. But the correct answer, “umbrella”, received only about 25%. That is a substantial gap. The training program measures this gap against the correct answer, then adjusts the parameters to raise the probability of “umbrella” for this input.

For example, it changes the parameters for “umbrella” to a = 0.60 and b = 1.20, while also adjusting the other candidates. The input remains x = 1, producing these scores and probabilities:

| Candidate | Score calculation | Score | Softmax probability |
| ---- | -------- | ---: | -----------: |
| umbrella | `0.60 × 1 + 1.20` | 1.80 | about 44.95% |
| raincoat | `0.40 × 1 + 1.00` | 1.40 | about 30.13% |
| hat | `0.30 × 1 + 0.91` | 1.21 | about 24.92% |

The input has not changed. The parameters and candidate scores have. After this adjustment, the predicted probability of “umbrella” rises from about 25% to about 45%.

**Step 4: Repeat prediction, comparison, and parameter updates.**

Initialization happens only once, at the start of training. After that, the program repeatedly predicts, compares with the source text, and adjusts the parameters based on the gap. It does not reset the initial values each round.

This adjustment does not happen all at once. It [must be repeated many times](https://arxiv.org/abs/2203.15556). The next demonstration keeps the same input so you can see how the probability of “umbrella” changes across training rounds.

<LLMMultiRoundTrainingDemo />

After many rounds of training, the model has learned statistical patterns in language and can generate grammatical, coherent text. It can understand the meaning of text and generate text that follows grammar and logic. This gives us a <JimmyNoteAnchor id="base-model">base model</JimmyNoteAnchor>.

<JimmyNote anchor="base-model">
  Pretraining gradually builds language ability. But being good at continuing text does not mean being good at answering a user's request. Chat models usually undergo further training. For this course, you only need to distinguish base models from chat models; we will not expand on those later training methods here.
</JimmyNote>

## 3. Why is this useful?

There is an important concept to remember: **a model's training data has a time cutoff.**

In other words, the model can only answer questions about information from before its training cutoff. Without [other tools (简体中文)](/zh/courses/llm-101/what-is-a-tool), it cannot obtain information outside its training data. For example, GPT-6's training data ends in April 2026, so it cannot know what happened after April.

A second important concept is that **the “correct answer” during training is not necessarily factually correct.**

Earlier, we said that the model checks the correct answer. Here, that answer is the next token in the training text. The text can contain errors, bias, or fiction. Predicting the source correctly does not mean that everything learned from it is factual.

For example, if all the training data says “a week has six days”, the model will think that a week has six days.
