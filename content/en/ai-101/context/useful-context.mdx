## Context is how you stop two different readings

A model sees the task, the files, and the tool results you provide. It does not automatically know a product decision you just made, and it may not know what a seemingly extra branch is protecting. Context is how the same task gets one reading.

A small change usually needs four kinds of information: where it happens, what it does now, what you want instead, and what must stay. A relevant fragment beats pasting the whole repository.

## Four kinds of information

| Information | What to say | One concrete example |
| --- | --- | --- |
| Location | Where it happens | The start button on the course overview |
| Current behavior | What it does now | The button opens the first lesson |
| Expected behavior | What should change | With a learning record, continue the last unfinished lesson |
| Constraint | What must stay | With no record, still start at the first lesson |

Do not mix the solution into the goal. If you are not sure where the problem is, ask the model to locate the code and explain how the data moves. Then you decide where to edit.

## Give an example someone can repeat

“Continue learning is broken” cannot be checked. You can write: finish lesson one, open lesson two, close the page, open the course overview again, and choose continue. If it still opens lesson one, give both the actual result and the expected result.

```text
Location: the course overview page
Current behavior: Continue opens the first lesson every time.
Expected behavior: Continue opens the last unfinished published lesson.
Constraint: without a valid record, open the first published lesson.
Acceptance: test both a new browser session and a returning learner.
```

A clear example also shows the edge. If the last lesson was withdrawn, where should continue go? Say that before the edit. It is easier to check than a patch after the fact.

<Callout title="Make the constraint specific" type="info">
“Don’t break it” cannot be checked. “Keep the current URL, add no dependency, and keep the first-lesson entry when there is no record” is a boundary you can tick off.
</Callout>

## Provide only what is relevant

Prefer the page, the component, and the data source involved. For a file you are unsure about, give the directory or a search result and let the model say what it still needs to read. Do not paste secrets, personal data, or a long log that has nothing to do with the task.

### Rewrite one vague request

Take a sentence like “improve search” and turn it into a task you can repeat. For example: during Chinese composition, Enter confirms the candidate and must not open search results.

Write the steps, the current behavior, the expected behavior, and the keyboard behavior to keep. Then ask the model to restate it. If the restatement is still vague, add context before you implement.

## Try it

Hand the task to someone who was not in the earlier discussion, or to a fresh conversation. If they can say where to start, what done means, and what must not move, the context is enough to start a small change. The next module turns those conditions into checks.
