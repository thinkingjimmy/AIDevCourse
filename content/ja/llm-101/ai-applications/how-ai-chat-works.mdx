大規模言語モデルが内容を生成する仕組みを説明したので、ここからは ChatGPT や DeepSeek App などの Chat 製品に目を向けましょう。

こうした製品を使っていると、LLM は前に話したことを覚えているように感じます。いったい、どうやって覚えているのでしょうか？

## 1. なぜモデルはあなたを覚えているように見えるのか？

Chat 製品を開いて、次のように試してみてください。まず LLM にこのような指示を出すと、次のような回答が返るかもしれません。

<Chat>
<ChatMessage from="user">
私の名前は Jimmy です。これからの回答はすべて Jimmy で始めてください。
</ChatMessage>

<ChatMessage from="assistant">
Jimmy、わかりました。これからは毎回「Jimmy」で回答を始めます。何について話しましょうか？
</ChatMessage>
</Chat>

続けて、こう聞きます。

<Chat>
<ChatMessage from="user">
今日の広州の天気はどうですか？
</ChatMessage>

<ChatMessage from="assistant">
Jimmy、今日の広州は晴れで、気温は 28 度です。
</ChatMessage>
</Chat>

最初の回答に Jimmy が入るのはわかります。では、なぜ 2 回目の回答も Jimmy で始まるのでしょうか？

[前の授業](/ja/courses/llm-101/what-a-language-model-does)で学んだように、モデルは受け取った入力と学習済みパラメーターから確率を計算します。「今日の広州の天気はどうですか？」だけを受け取ったなら、入力に名前も指示もありません。それなのに、なぜ Jimmy で始めるのでしょうか？

2 回目の回答に出てくる Jimmy は、どこから来たのでしょうか？

## <JimmyNoteAnchor id="001">2. 質問はどうやってモデルに届くのか？</JimmyNoteAnchor>

JSON は、インターネットで最も広く使われているデータ交換形式です。人が読み書きしやすく、機械も解析や生成をしやすい形式です。今は JSON を完全に理解する必要はありません。データ形式の一つだとわかれば十分です。

<JimmyNote anchor="001">
  この授業から、開発に関する知識を少しずつ扱います。興味があれば、この部分はさっと読み、DeepSeek 101 の [AI Chat を使うときのアドバイス](/ja/courses/deepseek-101/ai-chat-advice) と [AI Chat の実用的な使い方](/ja/courses/deepseek-101/ai-chat-tips) を重点的に読んでもかまいません。
</JimmyNote>

回答の Jimmy がどこから来たかを説明するために、まず Chat 製品のメッセージがモデル提供元のサーバーに届く仕組みを見ましょう。

提供元のサーバーは、スーパーコンピューターのようなものだと考えてください。製品から情報を受け取ると、モデルのプログラムを起動し、メッセージを入力して回答を生成します。その回答を製品に返し、製品がユーザーに表示します。

この流れは手紙を送ることに似ています。ただし、返事をもらうには決まった書式を使う必要があります。その書式に従わなければ、モデルの提供元は返事をくれません。

<ChatMessageSequence />

順番に見ていきましょう。

まず入力欄に「私の名前は Jimmy です。これからの回答はすべて Jimmy で始めてください。」などと入力し、送信します。Chat 製品は、この文章をそのまま提供元のサーバーに送りません。先に JSON 形式に変換してから送ります。おおよそ次のような形です。

```json
{
  "model": "deepseek-flash",
  "messages": [
    {
      "role": "user",
      "content": "私の名前は Jimmy です。これからの回答はすべて Jimmy で始めてください。"
    },
  ]
}
```

<JimmyNoteAnchor id="002">JSON</JimmyNoteAnchor> は、インターネットで最も広く使われているデータ交換形式です。人が読み書きしやすく、機械も解析や生成をしやすい形式です。今は完全に理解しなくても、データ形式の一つだとわかれば十分です。

<JimmyNote anchor="002">
  JSON について詳しく知りたい場合は、別のチュートリアル [JSON basics（简体中文）](/zh/courses/coding-101/what-is-json) を参照してください。
</JimmyNote>

この「手紙」は、申請用紙に記入するようなものと考えられます。空欄の用紙は、おおよそ次のような形です。この書き方に従わなければ、返事は来ません。

```json
{
  "model": "",   // ← モデル名を入力します。例：deepseek-flash
  "messages": [
    {
      "role": "",   // ← 役割を入力します。user はユーザーのメッセージ、assistant はモデルの回答です
      "content": "",   // ← 内容を入力します。例： "私の名前は Jimmy です。これからの回答はすべて Jimmy で始めてください。"
    },
  ]
}
```

この JSON を 1 行ずつ見てみましょう。最初は呼び出すモデルの名前です。ここでは deepseek-flash を使います。別のモデル名を入力すると、提供元のサーバーに、どのモデルで答えるかを伝えられます。deepseek-pro に変えれば、そのモデルで答えるように指定できます。

```json
{
  "model": "deepseek-flash",
}
```
次は messages 配列です。配列の意味を詳しく学ぶ必要はなく、データ構造の一つだとわかれば十分です。ここには過去のメッセージがすべて入ります。初めて送る場合は 1 件だけです。誰が送ったかは role で区別します。user はユーザーのメッセージ、assistant はモデルの回答です。

```json
{
  "messages": [
    {
      "role": "user",
      "content": "私の名前は Jimmy です。これからの回答はすべて Jimmy で始めてください。"
    },
  ]
}
```

製品がこのメッセージを送ると、サーバーは手紙を受け取り、モデルのプログラムに渡します。プログラムが実行を終えると、似た形の「手紙」を製品に返します。

```json
{

  "message": {
    "role": "assistant",
    "content": "Jimmy、わかりました。これからは毎回「Jimmy」で回答を始めます。何について話しましょうか？"
  }

}
```

最後に製品が「手紙」から必要な情報を取り出し、UI を通してユーザーに表示します。

<Chat>
<ChatMessage from="assistant">
Jimmy、わかりました。これからは毎回「Jimmy」で回答を始めます。何について話しましょうか？
</ChatMessage>
</Chat>

## 3. モデルは実際に何を受け取るのか？

質問がモデルに届く仕組みがわかったので、その後の回答も Jimmy で始まる理由を説明しましょう。

ユーザーが 2 件目のメッセージを送るとき、Chat が書く手紙は変わります。2 件目だけでなく、最初のメッセージとモデルの回答も含めます。

```json
{
  "model": "deepseek-flash",
  "messages": [
    {
      "role": "user", 
      "content": "私の名前は Jimmy です。これからの回答はすべて Jimmy で始めてください。" // ユーザーの最初のメッセージ
    },
    {
      "role": "assistant",
      "content": "Jimmy、わかりました。これからは毎回「Jimmy」で回答を始めます。何について話しましょうか？" // モデルの最初の回答
    },
    {
      "role": "user",
      "content": "今日の広州の天気はどうですか？" // ユーザーの 2 番目のメッセージ
    }
  ]
}
```

この手紙には過去のメッセージが入っています。それが、その後の回答も Jimmy で始まる理由です。

モデルがあなたを覚えたのではなく、毎回すべての過去のメッセージを受け取っているのです。

## 4. この仕組みを知ると何に役立つのか？

[トークンとは？](/ja/courses/llm-101/what-is-a-token)で学んだように、各モデルのコンテキストウィンドウには上限があります。たとえば DeepSeek-V4.1-Flash の上限は 128000 トークンです。

先ほど説明したように、Chat 製品は通常、過去のメッセージもまとめて送ります。会話が長くなるほどコンテキストも増え、モデルの上限を超えることもあります。

そのため、実際に送られるのは一部を削った内容かもしれません。上限を超えた部分はモデルに届かず、忘れたように見える場合があります。現在の製品にはこの問題を軽減する方法もあります。後で説明しますが、コンテキストをすべて入力する場合には及びません。

そこで、一つの会話ですべての用事を済ませず、一つの用事に一つの会話を使うのがおすすめです。モデルが忘れたようになる可能性を減らせます。入力するコンテキストが短くなるので、費用も抑えられます。
