前の授業では[Tool とは？](/ja/courses/llm-101/what-is-a-tool)を学び、モデルが検索のような外部の能力をプログラムに実行させるよう要求できることを知りました。ただ、それはリクエストの一部にすぎません。この授業では流れを一度戻して、モデルが回答を生成し始める前に、一体何を受け取っているのかを見ていきます。

先に混同しやすい点を整理しておきます。使えるツールの一覧は、リクエストの中の `tools` という別のフィールドでモデルに送られるもので、System Prompt の中ではありません。この授業で扱うのは、同じリクエストの中にあるもう一つの見えない部分、system メッセージ、つまり System Prompt です。

## 1. System Prompt とは何か？

System Prompt（システムプロンプト）は、Chat 製品の開発者が製品にあらかじめ書いておいた指示文です。チャット画面には表示されませんが、毎回のリクエストで messages の最初のメッセージとして、あなたの質問や会話履歴と一緒にモデルへ送られます。

製品の「初期設定」のようなものだと考えてください。モデルがどんな役割を演じ、どんな口調で話し、どんなルールに従って答えるかを決めています。書かれている内容は製品ごとに異なり、ユーザーは通常その中身を見ることができません。

## 2. System Prompt はどうやってリクエストに入るのか？

[AI Chat はどう動くのか？](/ja/courses/llm-101/how-ai-chat-works)で見た JSON を思い出してください。messages 配列では role によって誰が話したメッセージかを区別します。今回は最初のメッセージに注目します。

```json
{
  "model": "deepseek-flash",
  "messages": [
    {
      "role": "system",
      "content": "あなたは親切な AI アシスタントです。日本語で回答し、口調は親しみやすく、できるだけ簡潔に答えてください。"
    },
    {
      "role": "user",
      "content": "休暇届のメールを書いてください。"
    }
  ]
}
```

role が system のこのメッセージは、あなたの入力から来たものではなく、画面にも表示されません。あなたが見るのは自分の質問とモデルの返答だけで、System Prompt はずっと背後に隠れています。

しかも、送られるのは最初の 1 回だけではありません。「もう少し正式にして」と続けて補足すると、製品は配列全体を組み立て直し、system メッセージはやはり先頭に置かれます。

```json
{
  "model": "deepseek-flash",
  "messages": [
    {
      "role": "system",
      "content": "あなたは親切な AI アシスタントです。日本語で回答し、口調は親しみやすく、できるだけ簡潔に答えてください。"
    },
    {
      "role": "user",
      "content": "休暇届のメールを書いてください。"
    },
    {
      "role": "assistant",
      "content": "はい、こちらが休暇届メールの下書きです：……"
    },
    {
      "role": "user",
      "content": "もう少し正式にしてください。"
    }
  ]
}
```

これは前に説明したチャット履歴と同じ理屈です。モデルは自分では何も覚えておらず、毎回、製品が組み立て直した一連の内容を受け取っています。

## 3. System Prompt には何が書かれているのか？

製品によって書かれている内容は異なりますが、通常は次のような種類が含まれます。

- 身分と口調：モデルにどんな役割を演じさせ、どんなスタイルで話させるか。
- 言語と形式：どの言語で答えるか、リストや表、特定の構造を使うかどうか。
- 安全と境界：どの質問を拒否するか、敏感な話題にどう対応するか。
- ツールの使い方のルール：どんなときにツールを呼び出し、返ってきた結果をどう扱うか。どんなツールが使えるか、各ツールをどう使うかは通常、System Prompt ではなく、リクエスト内の `tools` フィールドで送られます。

製品によっては、自分で「カスタム指示」や「システムプロンプト」を書けるものもあります。それは製品が用意した内容と一緒に送られます。どう統合されるか、変更できるかは、製品ごとに異なります。<JimmyNoteAnchor id="001">System Prompt</JimmyNoteAnchor>

<JimmyNote anchor="001">
  製品が更新されると、System Prompt の内容も変わる可能性があります。同じ質問でも時期によって答えが変わる理由の一つです。それはあなたの質問と同じように Token を消費し、[コンテキストウィンドウ](/ja/courses/llm-101/what-is-a-token)にも含まれます。
</JimmyNote>

## 4. これはあなたにとって何を意味するのか？

- 通常、System Prompt の具体的な内容は見えず、モデルの回答から製品の設定を推測するしかありません。
- 同じ質問でも製品によって回答のスタイルが違うのは、一部にはここが理由です。それぞれ異なる System Prompt を携えているからです。
- System Prompt は入力の一部にすぎず、モデルが必ず従うことを保証するものではありません。回答をある形式や要件に合わせたいなら、自分の質問に直接書くのがよいでしょう。
- モデルとアプリの安全ルールは、主に製品側が決めています。重要なことは自分で確認する必要があり、製品が「ルールを備えているように見える」からといって、結果を完全に信じてはいけません。
