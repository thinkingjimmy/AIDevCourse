先聊一个容易被跳过的问题：**AI 已经能自己写代码、自己改文件了，为什么还要专门学 Agent？**

会用 AI 写代码，和会指挥 Agent 把一件事做完，是两种能力。前者像让助理帮你写一段文字；后者像把一个项目交给助理，你需要说清目标、给足材料、划好权限，还要能判断它有没有做对。

Agent 101 练的是后一种能力。

## 一、为什么还要学 Agent？

模型变强以后，很多操作可以一句话完成。但任务一长，问题就会暴露：

- 它有没有理解对目标？
- 它改了哪些文件？为什么改？
- 它执行的命令安全吗？
- 它说「完成了」，结果真的对吗？
- 它卡住时，应该继续、换方法，还是交给人？

这些问题不会因为模型变聪明就自动消失。Agent 越多地替我们行动，我们越需要能判断、能约束、能验证。

所以这门课不是教你「怎么让 AI 更听话」，而是教你**怎样把任务交给 Agent，并对结果负责**。

## 二、这门课和 LLM 101、Coding 101 有什么区别？

| 课程 | 关注点 | 学完能做什么 |
| --- | --- | --- |
| LLM 101 | 模型怎么生成回答、上下文和工具调用 | 理解 AI 的能力边界，用好 Chat |
| Coding 101 | 从零做出一个网站，理解前端、后端和数据库 | 在 AI 帮助下完成一个能上线的作品 |
| Agent 101 | 让 Agent 围绕目标连续执行，并验证结果 | 给 Agent 目标、上下文、权限和停止条件，完成可验证的任务 |

LLM 101 讲「模型能做什么」，Coding 101 讲「怎么把作品做出来」，Agent 101 讲「怎么让 AI 把任务持续做完」。

## 三、你会学会什么

| 能力 | 具体内容 | 怎么验证 |
| --- | --- | --- |
| 看懂执行循环 | 观察、判断、行动、检查；分清模型的判断和工具的实际操作 | 能画出一次任务的执行轨迹 |
| 写清目标与上下文 | 目标、材料、限制、完成标准；知道何时补充上下文 | 同一个任务，改进要求后结果更稳定 |
| 设置工具与权限 | Agent 能读写什么、危险操作的边界、最小权限 | 能说清每次授权允许了哪些操作 |
| 设定停止条件 | 怎样算完成、失败几次后重试或交给人 | 能让 Agent 停下来，而不是无限打转 |
| 使用 Coding Agent | 读代码、改代码、运行测试、看日志和截图 | 用实际运行结果检查改动 |

## 四、开始前要准备什么

- 先完成 LLM 101，特别是最后一课[「什么是 Agent？」](/zh/courses/llm-101/what-is-an-agent)。你需要知道模型怎么生成回答、上下文怎么进入输入、工具调用由谁执行。
- 建议完成 Coding 101。能读懂 JSON、跑起一个项目、用 Git 保存修改，后面的练习会顺利很多；可以先看[「关于这门课」](/zh/courses/coding-101/about-this-course)了解它的路线。
- 一个可以运行的小项目。Coding 101 里做的导航站就很合适；没有的话，准备一个你熟悉的项目也可以。
- 一个能读写项目文件的 Coding Agent 工具，以及基本的终端操作。用哪个工具不限。
- 不需要机器学习或模型训练背景。

<Callout title="给 Agent 权限前，先定边界" type="warning">
Agent 可能删除文件、运行命令、发起网络请求。第一次使用时，先限定可以访问的目录和可以执行的命令；不要把密钥写进提示里；重要改动先用 Git 提交；不确定的操作先问人。
</Callout>

## 五、怎么学

这门课尽量让每个概念都对应一个能执行、能检查的任务：

1. 先读懂概念，知道这一步在解决什么问题。
2. 给 Agent 一个明确的小目标，让它先说明计划。
3. 看它改了哪些文件、执行了哪些命令，再决定是否继续。
4. 用运行结果验证，而不是只读它的总结。
5. 失败时收集证据：完整报错、截图、日志、改动前后的差异。

几个习惯会让过程稳定很多：

- **先小后大。** 一次只让 Agent 做一件事，做完验证再进入下一步。
- **让它解释。** 每次改动后，要求它说明改了什么、为什么这样改。
- **用证据说话。** 「应该可以了」不算完成，跑起来、看到结果才算。
- **出错先停。** 连续失败时不要盲目重试，先看它卡在哪一步。
