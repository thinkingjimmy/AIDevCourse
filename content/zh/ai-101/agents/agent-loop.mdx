## 聊天停在回复，循环停在条件

聊天是你发一句、它回一句，下一步仍由你决定。Agent 会自己接下去：看当前状态，选一个动作，调用工具，读工具结果，再决定继续还是停止。这个来回就是 Agent 循环。

循环不是更聪明的聊天。它多出来的是行动权。行动权没有边界，就会改到你没看过的文件，或者重复尝试直到把环境弄乱。

## 一轮里实际发生的事

可以把它收成四步。产品的界面不同，顺序大致如此：

1. 观察：读你的任务、规则，以及已经打开的文件或上一步的工具结果。
2. 决定：选择下一步是回复你，还是调用某个工具。
3. 行动：真正去读、写、搜索或运行命令。没有权限的行动应该停住。
4. 再观察：把工具的输出放回窗口，判断是否满足停止条件。

停止条件要在开始前就有。例如“只改这一个按钮的文字，并且差异里没有别的文件”。没有停止条件，循环会把“再试一次”当成进度。

### 各步你该看什么

| 步骤 | 你要确认的事 | 失控时的样子 |
| --- | --- | --- |
| 观察 | 它引用的是不是你指定的文件 | 它根据不存在的文件开始改 |
| 决定 | 下一步是否还在任务里面 | 它顺手重构旁边的模块 |
| 行动 | 工具是否被允许 | 它在你没同意时运行安装或删除 |
| 再观察 | 结果是否被拿来核对，而不是被忽略 | 同一条报错被重复尝试很多次 |

<Callout title="循环可以随时停" type="info">
你不需要等它宣布完成。看到行动偏离任务，就停下，把允许的下一步写成一句新的约束。
</Callout>

## 用一小段轨迹看懂它

下面不是某个产品的真实日志，只是帮助你认这四步。真正使用时，以你的工具实际显示的工具名和输出为准。

```text
Observe: primary button label is "Browse courses"; href is /zh/courses.
Decide: edit the label only.
Act: replace the visible text with "Start learning".
Observe: href unchanged. Stop.
```

如果 `Act` 里出现了任务没提的文件，循环就已经越界。这时要停，不要让它“顺便修好”。多走的那一步往往比原来的任务更难撤回，因为你还没看过差异。

## 动手练习

用你自己的话把一个小任务写成停止条件：允许改什么、禁止改什么、最多看几处差异。然后想象循环走了三步，写出每一步你要看的证据。写不出证据的那一步，就不要交给 Agent 自动做。
