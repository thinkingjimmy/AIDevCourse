## 走完一个能解释的闭环

第一次和 AI 一起改代码，重要的不是一次做出完整产品，而是走完一个你能讲清的闭环：目标、上下文、约束、修改、验证、安全复查。选一个你已经能运行的页面，例如只有标题和按钮的练习页。

这一课的任务仍然很小：把主按钮的文字改成 `Start learning`，保留原来的点击行为。小，是为了让每一层检查都看得见。

![一次小修改的闭环：目标、上下文、修改、验证和安全复查](/images/courses/change-cycle.svg)

## 先把任务写成可以验收的话

“帮我优化页面”没有说明什么叫更好。换成“把主按钮文字改为 Start learning，保留点击后进入课程列表的行为”，边界就出现了。

可以直接使用这样的说明：

> Find the primary learning button. Change its visible label to “Start learning”. Keep its destination and all other behavior unchanged. Explain which file you changed and how you checked the result.

同时告诉模型你在哪个页面看到这个按钮。已经知道组件路径就一并给出。不要为了显得完整而粘贴整个项目。

### 看懂最小差异

修改前可能是：

```tsx
export function LearningLink() {
  return <a href="/zh/courses">Browse courses</a>;
}
```

期望的结果是：

```tsx
export function LearningLink() {
  return <a href="/zh/courses">Start learning</a>;
}
```

比较两段：显示文字变了，链接地址没有变。任务没有要求换颜色、拆组件或改路由，这些都不属于这次修改。

<Callout title="先理解，再接受" type="info">
如果你无法解释某一处修改为什么必要，先让模型说明。能运行不代表改动范围正确。
</Callout>

## 按顺序做完四步

1. 上下文：写出位置、当前文字、期望文字，以及必须保持的链接。
2. 约束：不改地址，不新增依赖，不调整无关样式。
3. 验证：在页面上看文字，用鼠标和键盘各操作一次，再看文件差异是否只有这一处。
4. 安全复查：确认没有贴出密钥，没有多出来的请求或依赖，没有你不认识的文件。

使用项目说明里已经记录的方式打开页面。查看差异时，核对是不是只动了相关文件。运行项目现有的检查命令，并记下真实输出。检查失败时，先判断是这次修改引起的，还是环境里原来就有的问题。

## 动手练习

在一个你能本地运行的练习项目里，只改一个链接或按钮的文字。用四句话留下记录：上下文是什么、约束是什么、你看到的验证结果是什么、安全复查还剩什么限制。

- [ ] 新文字与任务一致。
- [ ] 原来的点击目标不变。
- [ ] 键盘仍可聚焦并操作。
- [ ] 差异里没有无关修改，也没有密钥。

四项里有一项没有证据，就继续查。确认之后，再用页面底部的完成标记。读到这里本身不会自动完成课时。
