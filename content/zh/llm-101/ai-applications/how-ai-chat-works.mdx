讲完大语言模型如何生成内容后，我们再将视角转移到现在市面上的各种 Chat 产品上，比如 ChatGPT、DeepSeek App 等产品。

当你在使用这些 Chat 产品的时候，可能会有这样的一个疑惑，跟 LLM 聊多了之后，好像 LLM 会记得你说过的话那样。

## 一、为什么模型能记住你？

你可以打开各种 Chat 产品进行如下测试。先给 LLM 下达类似的指令：

<Chat>
<ChatMessage from="user">
我叫 Jimmy。你后续的回答都要以 Jimmy 开头。
</ChatMessage>

<ChatMessage from="assistant">
Jimmy，好的，我记住了。后续每次回答我都会以“Jimmy”开头。请问你想聊什么？
</ChatMessage>
</Chat>

然后再问：

<Chat>
<ChatMessage from="user">
今天广州的天气如何？
</ChatMessage>

<ChatMessage from="assistant">
Jimmy，今天广州天气晴朗，温度在 28 摄氏度。
</ChatMessage>
</Chat>

咦？第一次回答带 Jimmy 还比较好理解。为何第二次回答也会以 Jimmy 开头了？

按照前面学到的生成原理，模型会根据收到的输入和训练得到的参数计算概率。如果它只收到「今天广州的天气如何？」这句话，输入里没有我的名字和要求，为什么还会用 Jimmy 开头？

那第二次的回答里 Jimmy 是从哪里来的呢？

## 二、你的提问是如何被发送给模型的？

为了解释清楚回答里的 Jimmy 是从哪里来的，我们需要先简单了解下当用户使用 Chat 产品时，消息是如何传递到模型厂商的服务器的。

你可以简单将模型厂商的服务器理解为一台超级计算机，它会接收来自产品的信息，收到产品的信息后，它会启动模型程序，输入消息内容，然后生成回复，再将回复发送到产品，产品再将接收到的信息呈现给用户。整个过程就像是你寄信，但如果你想要得到回信，就需要使用一种很特殊的写信的格式。如果不按照这个格式写，模型厂商就不会给你回信。

<ChatMessageSequence />

我们一步步来看这个过程。

首先当你在输入框里输入内容比如「我叫 Jimmy。你后续的回答都要以 Jimmy 开头。」，点击发送后，Chat 产品并不会马上将你输入的这段内容发送给模型厂商的服务器，而是会先将其转换为 JSON 格式，接着再发送给模型厂商的服务器，它大概是这样的：

```json
{
  "model": "deepseek-flash",
  "messages": [
    {
      "role": "user",
      "content": "我叫 Jimmy。你后续的回答都要以 Jimmy 开头。"
    },
  ]
}
```

JSON 格式是互联网上最通用的数据交换格式，它易于人阅读和编写，也易于机器解析和生成。你现在不需要完全理解 JSON 格式，只需要知道它是一种数据格式即可（如果想聊了解更多 JSON 格式相关的内容，可以参考我的另一篇教程 [JSON basics](/zh/courses/coding-101/what-is-json)）。

我们可以一行行来分析一下这个 JSON 格式。首先，第一行是调用模型的名称，这里我们使用的是 deepseek-flash 模型。在此输入不同的模型，就是告知模型厂商的服务器使用何种模型进行回答。如果换成 deepseek-pro 模型，就是告知模型厂商的服务器，使用何种模型进行回答。

```json
{
  "model": "deepseek-flash",
}
```
第二行是 messages 数组（数组是什么意思，你也不需要深究，只需要知道它是一种数据结构即可），数组中包含所有历史消息。假设是第一次发送消息，那么数组中只有一条消息，并且为了区分这条消息是谁发送的，会用 role 来区分，user 表示用户消息，assistant 表示模型回复：

```json
{
  "messages": [
    {
      "role": "user",
      "content": "我叫 Jimmy。你后续的回答都要以 Jimmy 开头。"
    },
  ]
}
```

你可以简单地将这封「信」看成类似填一个申请表。然后这个表格空白状态大概是这样：

```json
{
  "model": "",   // ← 填写模型名称，比如 deepseek-flash
  "messages": [
    {
      "role": "",   // ← 填写角色，user 表示用户消息，assistant 表示模型回复
      "content": "",   // ← 填写内容，比如 "我叫 Jimmy。你后续的回答都要以 Jimmy 开头。"
    },
  ]
}
```

产品发送了这条消息后，服务器收到这封信后，将其给模型程序，运行完后，再以类似的「信」发送给产品：

```json
{

  "message": {
    "role": "assistant",
    "content": "Jimmy，好的，我记住了。后续每次回答我都会以“Jimmy”开头。请问你想聊什么？"
  }

}
```

然后产品会从这封「信」里提取必要的信息，然后通过 UI 显示给用户：

<Chat>
<ChatMessage from="assistant">
Jimmy，好的，我记住了。后续每次回答我都会以“Jimmy”开头。请问你想聊什么？
</ChatMessage>
</Chat>

## 三、模型实际收到的内容是什么？

了解完你的提问是如何被发送给模型的，我们再来解答一下为何后续的回答里，LLM 仍然会用 Jimmy 开头的原因。

当用户发送第二条消息的时候，Chat 写的信会不一样，它并不会仅仅仅包含你第二条消息，而是会包含你第一条消息和模型回复：

```json
{
  "model": "deepseek-flash",
  "messages": [
    {
      "role": "user", 
      "content": "我叫 Jimmy。你后续的回答都要以 Jimmy 开头。" // 用户发送的第一条消息
    },
    {
      "role": "assistant",
      "content": "Jimmy，好的，我记住了。后续每次回答我都会以“Jimmy”开头。请问你想聊什么？" // 模型回复的第一条消息
    },
    {
      "role": "user",
      "content": "今天广州的天气如何？" // 用户发送的第二条消息
    }
  ]
}
```

可以看到这封信里包含了历史的消息记录，这就是为什么后续的回答里，LLM 仍然会用 Jimmy 开头的原因。
