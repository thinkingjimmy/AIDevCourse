前面一章我们聊到开源模型相关的场景疑问后，本章我们聊聊如何选择适合自己的大语言模型。

## Q1：如何评判哪个模型更强？

首先需要明确一点，强弱是相对的概念。截至到 2026 年 11 月，我暂时没有看到一个各方面都完美的模型。

擅长中文写作，不代表擅长修复代码。擅长写代码的，可能性价比比较低。那要如何评判哪个模型更强呢？

目前常见的公开评测有以下两种：

- **标准化测试（Benchmark）**：让不同模型完成一组任务，再按规则评分。比如知识问答、数学解题、代码修复等。它可以帮助我们比较模型在某些任务上的表现。常见的标准化测试有 [DeepSWE](https://deepswe.datacurve.ai/)、[TerminalBench](https://www.tbench.ai/) 等，也有一些相对垂直的评测，比如专门评测模型开发 Android 应用的跑分 [Android Bench](https://developer.android.com/bench) 等。如果你明确知道自己要做什么任务，可以先看看有没有对应的评测。
- **人类偏好评测**：把同一个问题交给不同模型，在隐藏模型身份的情况下，让人选择更喜欢的回答。它有助于观察哪些回答更符合参与者的偏好，但「更喜欢」和「事实更准确」并不是同一个标准。比如常见的 [Arena AI](https://arena.ai/) 的前端评测，则是让参与者选择哪个模型实现的前端界面更好看更符合要求。那好看与否就会相对比较主观。

不过不管是哪种测评，都只能作为参考，不能完全依赖。因为模型的强弱是相对的，而且评测的场景和任务可能与你的实际需求不完全一致。


如果你不知道选择哪个模型更好，可以考虑查看我的另一个网站 [Vibe Coding Navigator](https://vibecodingnav.com)，这个网站统计了目前所有主流大模型的评测结果，你可以根据这个网站的统计结果来选择适合你的模型。

所以，截至到 2026 年 11 月，我选择使用的模型和工具是：

- Grok Bot：目前这个产品会自动路由模型，有可能会路由到 X 的 Grok 模型也有可能是 Claude 的模型。但因为其产品体验比较好，所以 Personal Agent 我会选择它。后续章节我们会展开聊下什么是 Person Agent。
- Claude Code：如果需要写代码，我会选择 Claude Code。然后模型我会选择 Opus 5.5。Codex 只能算是备胎，Claude Code 的用量用完了，我会选择使用 Codex。但 computer use 场景我会用 Codex。比如让AI 控制某些应用，或者控制浏览器，我就会用 Codex。
- Gemini：Google 的模型是真的很一般，我不会用它来写代码，但 Gemini 的模型写文本倒是挺不错的。
- DeepSeek：我目前用它的场景相对比较少，包括其余的国产模型，如果你能用更好的模型，且成本也能接受的话，你大概率不会使用更差的模型。

这里我展开聊下我对模型价格的看法。

很多时候，我们看模型的价格，不能纯看他们的价目表上的绝对价格。这些价格可能很低，但这并不代表你实际使用时，所花费的成本。

举个例子，某个模型 A 每百万 Token 只要 1 美元，另一个模型 B 要 5 美元。但如果 A 模型需要花费 1000 万 Token 才能完成认为，而 B 模型只需要 100 万 Token 就能完成任务，那么实际使用时，A 模型的成本其实是比 B 模型要高的。

更不用说，如果你拿 A 模型写代码，因为模型能力不行，写出来了一些带 Bug 的代码，导致需要花费你更多的时间去修复，那么实际使用时，A 模型的金钱以及时间成本其实是比 B 模型要高的。

另外，现在很多模型厂商都会提供一些订阅套餐，然后在订阅期限内，一般会有一些单位时间内可以使用多少 Token 的限制，比如 5 小时限制，一周的限制。不过一般模型厂商并不会公开告知这个限制是多少，并且还会时常根据市场的反馈进行调整。

截至到 2026 年，Claude Code 和 Codex 的订阅套餐依然是目前最具性价比的套餐。实际能使用的 Token 数量，如果按照 API 的价格计算，会远远超过订阅费用。如果预算充足，我依然建议你订阅顶级模型的订阅套餐，而不是为了省钱去订阅那些相对便宜的模型。

当然，如果你只是想用 AI 来解决一些相对简单的任务，那或许 DeepSeek 会是不错的选择。但可惜它没有提供订阅套餐，你只能按需购买 API 调用次数。
