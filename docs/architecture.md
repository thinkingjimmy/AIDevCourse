# Architecture

The site uses Next.js App Router, React, Fumadocs MDX, next-intl, and Tailwind CSS. Exact versions live in `package.json` and `pnpm-lock.yaml`. Use Node 22.17.0 or a later 22.x patch, or Node 24.x, and pnpm 10.30.3. CI and production remain on Node 22.x. Core reading needs no database or external content service; optional link previews read public metadata, and authored X/YouTube embeds connect directly to their platforms in the browser.

## Module boundaries

| Module | Responsibility |
| --- | --- |
| [app](../src/app/) | Compose routes, static metadata, locale providers, and public search responses. |
| [components](../src/components/) | Keep course, layout, MDX, progress, search, and illustration behavior together by purpose. |
| [content](../src/lib/content/) | Scan, validate, compile, and query the published catalog. |
| [i18n](../src/lib/i18n/) | Supported languages, preference negotiation, dictionaries, and URL parsing. |
| [lib](../src/lib/) | Small shared progress, search, metadata, redirect, and utility modules. |
| [styles](../src/styles/) | Shared Tailwind theme, typography scale, and @apply defaults for documents, Markdown, and SVG. |

Routes compose components and query server content. Browser components receive serializable catalog data; they must not import the filesystem scanner or compiled server modules. Course-only controls stay in `components/course`. Shared UI primitives stay in `components/ui`; dialogs share `ui/overlays`. The two hero illustrations share an animation driver while retaining their own markup and timing.

`components/mdx/notes` pairs inline text or standalone image JimmyNoteAnchor IDs with JimmyNote blocks. The image variant accepts exactly one Markdown image or image reference with meaningful alt text. Content validation checks the variant, block placement, stable identifiers, nonempty notes, unique one-to-one pairs, and records hasJimmyNotes in the catalog. NoteScope owns the article note registry, shared popover selection, and responsive rail; NoteEntry mounts each server-rendered card in the active location. The layout hook batches measurements in animation frames, tracks article/card/font/viewport changes, stacks cards with a 16px gap, and keeps the independent left outline available while notes occupy the right rail. Each text connector starts at the last highlighted fragment’s lower-right corner, follows a short diagonal lead, then runs horizontally into the card’s left border at the configured entry inset. Range measurements keep the lead below the full text line, including trailing rich text. Stacked cards route through the line gap and gutter before descending, so their connectors avoid article text. Image anchors retain the midpoint source on the image’s right edge. Shared note tokens own the reference orange (approximately #F38618), pale highlight, and 1.5px line width. Square white cards use matching orange borders and a 3px pale-orange offset shadow. The hook uses the border’s rendered width for SVG strokes and connection coordinates so device-pixel rounding cannot separate their weights. The rail reuses the existing 21rem column and 64rem lesson-container breakpoint, including notes without headings. Narrow anchors use a plain numeric superscript to open a Radix Popover with localized numbered action labels and native trigger focus handling. `lib/content/note-numbers` assigns compiler-owned noteNumber props to paired anchors and notes in two AST passes, using anchor order rather than declaration or hydration order. Every MDX document starts at 1, image anchors share the sequence, and code fences cannot consume numbers. This supplies stable server-rendered numbering for initial paint and no-JavaScript cards without changing lesson text or accepting author-supplied numbers. NoteAuthor keeps the matching number in a localized screen-reader-only description referenced by the card and popover. The author heading has no visible numeric suffix. Component previews accept a validated lang query to exercise all five UI dictionaries. Image anchors keep their original image and alt text in a figure, with an independent numbered marker inset 12px from its top and right edges; they do not apply the text highlight stroke. NoteAuthor keeps the localized article-author caption and uses five compact borderless icons: Star, Xiaohongshu, X, Bilibili, and a QR code. AuthorActionIcon owns all five SVG glyphs with a shared 1.5-unit stroke, rounded caps, and a 16px height; the Xiaohongshu wordmark uses regular-weight typography to match their visual weight. AuthorWechat shares the footer dialog’s QR placeholder. A controlled Radix QR popover supports delayed mouse hover, click pinning, keyboard dismissal, and focus return while retaining the outer note. Desktop controls are 32px with smaller glyphs and share the author row’s vertical center; wrapped popover controls align with the avatar’s left edge. Coarse pointers receive 44px targets. Each note includes a noscript card with native social links and a details-based QR disclosure at its authored position. KeyTakeaway and Achievement share FramedNote for the quotation border, offset shadow, embedded top-edge label, typography, and responsive spacing. The label stays in normal flow so wrapped achievement titles reserve space above the body. KeyTakeaway adds a decorative 💡 before its localized server label; its rich Markdown body and no-JavaScript reading remain available.

JimmyNote visual decision (2026-11-01): use the orange lower-right elbow direction selected from the annotation prototypes. The reference orange is approximately #F38618; the shared note tokens own its accent, pale highlight, and offset shadow. Keep square white cards, compact author actions, a short 12px diagonal lead, and a horizontal segment that meets the card’s left border 12px below its top. Use the last highlighted fragment so wrapped annotations remain attached to their end. Detached short tails and replacing wide connectors with numbered references were rejected because the selected wide direction keeps an explicit connection. The previous upper-right text connector was rejected because it crossed the following text. Image anchors connect from the midpoint of the image's right edge. Preserve all authored wording.

JimmyNote narrow-entry decision (2026-11-01): replace the comment glyph with a raised numeric marker. Use plain digits in every locale, localized accessible labels, and matching screen-reader-only note descriptions. Card headings show the author without repeating the entry number. Keep a 44px minimum target while removing the painted button surface. Numbers come from the compiler; authors retain the id/anchor pairing interface. Highlight tails and detached comment outlines were considered; the selected typographic marker fits the editorial highlight style.

`components/mdx/llm-training` owns independent one-round and multi-round demonstrations of 今天雨天，出门记得带…, with 伞, 雨衣, and 帽子 as candidates. Shared model data owns the input, target, candidate order, and probabilities. The single-round demo reuses FormulaTrainingModel across steps 00–03: parameter initialization, prediction, comparison, and adjustment. Initialization hides inputs and predictions; the original model stays mounted, and the updated model appears only in step 03. Candidate scores and softmax probabilities are calculated from fixed a/b coefficients and x = 1. The multi-round demo derives its first two probability distributions from those same formula models, then shows further illustrative training checkpoints. Each client component keeps independent bounded state. The MDX registry exposes both demos as parameterless, childless standalone blocks. Static no-JavaScript alternatives preserve all steps without changing achievements or browser storage.

`components/mdx/pretraining` owns the three-tab LLMPretrainingOverview used in the training lesson. Radix Tabs preserves keyboard navigation and selected-panel semantics. Each panel shows one hand-drawn illustration inside TrainingFrame; all three panels stay mounted to load their optimized images before selection, while inactive panels remain hidden. A shared 16:9 image area prevents layout shifts. The illustrations module owns static image imports, stage labels, accessible descriptions, and the shared Radix dialog for image enlargement with localized controls. The Tokenizer description derives from the tokenization module's shared text and IDs; its generated artwork must be updated when that example changes. WebP delivery assets live in public/images/courses/how-language-models-are-trained; PNG sources and prompts live in assets/how-language-models-are-trained-illustrations. The MDX registry and validator expose the same parameterless standalone block. A static fallback shows all three images without JavaScript or learning-storage changes.

The MDX anchor registry uses `components/mdx/link-preview` for Radix hover/focus cards and native navigation. `/api/link-preview` delegates to `lib/link-preview`: local pages read catalog summaries, while outbound requests require an exact published HTTPS link. The network boundary checks and pins public IPv4 DNS on every redirect, reads at most 256 KiB with a 4.5-second deadline, and returns text metadata with an optional public HTTPS cover. When the system resolver returns only proxy-generated addresses in 198.18.0.0/15, it queries Cloudflare's fixed HTTPS DNS endpoint for the hostname and applies the same public-IP checks to those answers. The hostname alone is sent to the resolver; private and reserved destinations remain blocked. Successful external metadata is cached for one hour; the browser shares bounded requests and uses short-lived failure entries. Unavailable remote metadata returns 204 with a short cache lifetime, while unsupported destinations retain 404. Reading and navigation work independently of remote metadata.

Local development uses `next dev --webpack` to avoid Turbopack CSS hot-replacement failures. Its in-memory Webpack cache avoids unsupported filesystem-cache tracing of dynamic imports in MDX and next-intl dependencies; production cache settings are unchanged. Its regression check starts a separate application copy, changes real CSS, verifies hot replacement without a page reload, and records browser errors and stylesheet responses.

Avoid single-file directory layers and unused generic APIs. A directory is useful when it owns a coherent group of files. Source files stay within 800 lines; each directory has at most eight maintained files.

`components/mdx/chat-sequence` owns ChatMessageSequence, the standalone request/response demonstration in how-ai-chat-works. The model defines two attempts and simplified request/response JSON. Playback advances discrete steps once, with visibility-aware timers and cleanup. A layout hook measures real message lines and anchors the current floating bubble and pointer to their midpoint; ResizeObserver handles content and container changes. Phosphor icons and semantic format colors distinguish invalid and valid requests. MDX validation rejects attributes, children, and inline use. No-JavaScript readers receive both complete static sequences; no model calls or learning-storage writes occur.

`components/mdx/chat` renders message bubbles and authored thinking/tool activity blocks. ChatActivity shares the official Trace/TraceCollapsible layout, collapsed-by-default state, 44px trigger, and native details fallback. ChatThinking and ChatToolCall each expose a boolean defaultOpen prop; both render paths follow that value. ChatToolCall follows the shadcn Radix Tool pattern; ChatThinking and ChatThinkingStatus follow its Reasoning pattern, using Thought with a completion icon for authored reasoning and a noninteractive running Thinking line for the empty ongoing state. Both completed activities keep the answer visible when manually collapsed. `components/ui/ai-elements` contains the upstream Trace, CodeBlock, and Collapsible sources and their MIT license, with project imports and Phosphor icons replacing registry placeholders. The MDX adapter converts highlighted code-fence children back to text for the official small, wrapping CodeBlockContent, without adding a browser highlighter or AI SDK. A server-localized completion label names each tool trigger. ChatMessage separates activity blocks from the final answer while keeping one assistant avatar and a stable content width. The MDX registry and validator expose static, nonempty name/title attributes for tool calls inside completed assistant messages, plus a bare defaultOpen flag or literal boolean expression for either completed activity. Other expressions remain forbidden. No tool execution or learning-storage writes occur. `/design/components#chat-tools` previews reasoning, a completed search, and the final answer together. Source patterns: [Tool](https://ui.shadcn.com/docs/ai-elements/radix/tool) and [Reasoning](https://ui.shadcn.com/docs/ai-elements/radix/reasoning).

## Styling

The homepage primary action has its own server-rendered treatment: a black surface with the shared small radius and a subtle shadow. Its link keeps a fixed hit area while the inner face and arrow animate with CSS transforms over 150ms. Fine-pointer hover advances only the arrow by 4px and keeps the face stationary; pressing inside the hit area scales the face to 96%. Combining `:active` with `:hover` cancels press feedback when the pointer leaves, including Firefox's persistent active-link state. Reduced-motion preferences disable transforms and transitions, and keyboard focus remains immediate. Course and missing-page actions retain their separate raised treatment.

Course Markdown follows the classic [shadcn Typography](https://v3.shadcn.com/docs/components/typography) heading hierarchy: H2 uses `text-3xl` (30px), H3 uses `text-2xl` (24px), and H4 uses `text-xl` (20px), all at weight 600. H2 adds a bottom border and 40px of space above it; H3 uses 32px. These rem-based sizes follow browser text preferences. The shared `course-prose` utility owns the rules and excludes `not-prose` components. Body text retains the 16px base size and locale-specific reading leading.

Tailwind is the sole application styling system. Components use utilities; native document rules and generated Markdown/SVG selectors use @apply. The shared [typography tokens](../src/styles/typography.css) defines rem-based sizes, unitless leading, font weights, and responsive title roles. Public pages and design previews import the same theme. The cn helper registers custom typography names with tailwind-merge so overrides do not remove font sizes when applying colors. Structure validation rejects numeric arbitrary typography values and literal CSS typography declarations.

Lesson pages cap the article column at 51rem (816px at the default root size, a 20% increase from 680px) and center the reading group in the available content area. On desktop viewports of at least 961px, lessons with headings reserve a 5rem left gutter. The fixed outline sits 0.5rem from the sidebar's right edge, follows its expanded or collapsed width through an inherited CSS variable, and stays vertically centered. Its entries start another 4px inside the rail. LessonToc accepts hasNotes to select the available-gutter threshold. At a lesson-container width of 72rem without notes or 95rem with notes, its width grows from 4rem to 14rem and displays complete wrapping heading text. These thresholds keep at least 1rem clear of the centered article, including its right note rail. A nested toc container query controls labels and markers before hydration; resizing or collapsing the sidebar switches modes without changing article geometry. Wide links use dark current text and omit marker previews and tooltips. The outline remains visible when the reading container is narrower than 64rem and scrolls independently on short screens. Jimmy notes retain a separate 21rem right rail with a 2rem gap, shown only at the 64rem lesson-container breakpoint; that reading group is capped at 74rem. Hide the outline on mobile, omit absent columns, and preserve full article width on lessons without headings or notes.

Below 961px, `components/course/navigation/mobile-navigation` replaces the lesson header with four persistent bottom actions: home, course contents, achievements, and author. Glisse 0.5.0 supplies one decorative Glass surface behind native links and Radix dialog triggers. Its scoped light material uses the shared mobile glass tokens with a 98% white fill and 24px blur to keep article text from competing with navigation; static CSS preserves first paint and no-JavaScript rendering. Reduced transparency, increased contrast, reduced motion, and unavailable backdrop filters have explicit fallbacks. The bar accounts for the bottom safe area, and SidebarInset reserves end-of-article space. The shared module tree lives in `components/course/navigation/module-tree`; mobile rows wrap and have 48px targets. Sidebar uses the shared sheet's bottom placement below the breakpoint, with a bounded dynamic height, a rounded top, and independently scrolling contents between a fixed header and footer. Existing route ownership closes the sheet on navigation or breakpoint changes. Without JavaScript, the Contents action opens a native details panel above the bar.

The sidebar footer contains the achievement gallery, a direct language dropdown, and a waving-hand author trigger, in that order. `components/course/author-card` owns the client author dialog and its responsive content. It reuses the shared Radix dialog, border/radius tokens, offset shadow, and frosted backdrop. Its header stays reachable while the content scrolls on short screens; narrow containers move the website and project actions onto separate rows. Public destinations and the optional WeChat QR image live in `lib/site-config`, and five `Author` dictionaries are supplied by the locale provider. No-JavaScript footers link directly to the author's website. The language dropdown reuses the header switcher's translation destinations, cookies, and fragment preservation, with five direct choices and no About entry or submenu. Its portal stays inside the footer to preserve mobile sheet focus behavior.

`components/mdx/chat/inline-citation.tsx` combines the official HoverCard source in `components/ui/ai-elements` with the shared Button, following [Inline Citation](https://ui.shadcn.com/docs/ai-elements/radix/inline-citation). A native anchor remains the trigger, so clicks, one-touch navigation, and no-JavaScript reading open the original source. Hover and keyboard focus show author-supplied metadata in a viewport-bounded portal; Escape dismisses it without moving focus. Five UI dictionaries name the source action and new-tab behavior. The MDX registry accepts inline, childless declarations with a static HTTPS URL and optional title/description, and the validator registers each source as a content link. No remote metadata requests are added. `/design/components#inline-citations` provides the shared preview.

`components/course/outline` owns the lesson outline's client enhancement. Its active-heading hook samples actual heading positions at most once per animation frame on passive page scroll, viewport changes, fragment navigation, font loading, and article resizing. The reading line follows the heading's existing scroll margin. The last section remains selectable near the article's end. In compact mode, native links use accessible heading text and 12px by 3px gray markers on 20px rows; the current marker uses the foreground color and `aria-current="location"`. A separate preview index controls hover and focus: marker widths fall from 52px to 40, 28, 20, and 12px with distance. Left-origin transforms animate for 150ms and stop under reduced motion. Radix Tooltip portals show only the previewed heading beside the rail, using the shared quote frame: a white background, square foreground border, 4px right/down border-colored shadow, and wrapping text capped at 20rem. No arrow or extra heading is added. The outline's localized name remains available to assistive technology. Keeping the current link visible scrolls only the outline; manual reading never rewrites the URL or browser history. Without JavaScript the server-rendered anchors remain available without a misleading static active state.

`components/mdx/embeds` provides XEmbed and YouTube. Both share the pure parsers in `lib/embeds/urls` with the content validator, accept only a static HTTPS url and optional nonempty title, and require a childless standalone block. Parsers extract platform IDs and start times, then construct fixed-origin embed and source URLs; they never pass through arbitrary iframe sources or share parameters. X uses a shared, retryable widgets.js promise with a ten-second script deadline. An IntersectionObserver with a 300px margin starts each post, and a fifteen-second total deadline handles failed or missing widget responses. Each effect owns a disposable DOM target; timeout and navigation detach it so late SDK writes cannot restore removed content. YouTube stays server-rendered with a lazy privacy-enhanced iframe, inline playback, no autoplay, and a 200px minimum height. Both reserve space. X shows its localized source link only after a loading failure or without JavaScript; a loaded post uses its own links. YouTube always keeps its source link. CSP permits frames only from the YouTube privacy-enhanced origin and the four exact X platform/syndication origins; object and ancestor restrictions remain in place. No API keys, server-side platform fetches, or new dependencies are required. Controlled E2E checks and an opt-in EMBED_LIVE=1 smoke check report separately whether platform frames were available; an HTTP 200 does not establish video playback.

## Content pipeline

`lib/content/mermaid` validates Mermaid fences with Pele and replaces them with a compiler-only MermaidDiagram before Shiki. The shared renderer disables diagram links and images so diagrams cannot bypass the content link and image checks. The server component renders SVG with per-instance React IDs for markers and accessibility references; the browser receives no diagram engine. Native horizontal scrolling preserves readable labels on narrow screens, and rem-based SVG dimensions follow the reader's text size. Site CSS variables supply colors and fonts. Both Markdown and MDX use this pipeline; ordinary code fences remain code. Syntax failures report the source file and original fence position during content validation and compilation.

1. Authors edit `content/{lang}` and explicitly order files in `meta.json`. Course-root index files infer course kind; other article paths infer lesson kind. Authors provide stable lesson IDs, titles, descriptions, and course ownership, without duration, classification, or revision fields.
2. `scan.ts`, `schema.ts`, `mdx.ts`, and `validate.ts` check identity, metadata, ordering, the safe MDX subset, image dimensions, and rendered link destinations. Validation uses the same Fumadocs YAML parser as compilation.
3. The Fumadocs configuration writes compiled modules and a catalog into `.source/` for public content or `.source-test/` for fixtures.
4. `source.ts` exposes server queries. Development reads and validates current content once per request through React cache; production reads the generated catalog. `manifest.ts` and `model.ts` define serializable courses, lessons, translation maps, and rendered anchors.
5. Routes, metadata, sitemap, and the search API consume the same published catalog.

The course overview renders frontmatter and the syllabus anchor `course-catalog`. Lesson pages render their body headings. Link validation and language switching use these rendered anchors. Course/module folders determine organization; public lesson URLs omit the module folder.

Body edits and achievement declarations support development hot reload. Current validated definitions and course achievement inventories come from the same request snapshot, so adding an achievement cannot leave its MDX binding on the startup catalog. Restart after frontmatter, filename, or ordering changes to refresh compiled routes. Do not edit generated files by hand.

## Routing and client state

`src/lib/i18n/routing.ts` owns canonical paths: English has no prefix; the other languages retain one. The catalog, UI, metadata, sitemap, search filtering, and link validation share this rule. `src/proxy.ts` negotiates only `/`, preserves explicit native homepage language choices, rewrites canonical English URLs to internal `/en` App Router routes, and validates published paths. Direct `/en` URLs redirect permanently to their canonical address; article and About URLs never negotiate language. Missing pages use static unavailable documents with a 404 status. Root and locale not-found adapters and proxy documents all use the single server-rendered MissingPage renderer, which owns localized copy and native recovery links. The locale layout also passes MissingPage as the SiteFrame recovery slot. SiteFrame exposes it through useErrorPage to the client runtime-error adapter and restores the header/footer for failed lesson routes; other routes reuse their existing frame. Runtime failures retain their actual error semantics. Native recovery navigation reloads the destination and clears failed client state. The root, locale, and design documents share pinned Fontsource WOFF2 assets and font variables from `src/styles/fonts.css`, with unicode-range CJK subsets loaded only when used. Font compilation has no Google network dependency; 404 titles and decorative numerals use regular-weight Geist Pixel with locale-specific glyph fallbacks, and both recovery buttons reuse the homepage Hero's action-raised variant. Framework route adapters remain separate from this one presentation. Changes to the routing adapter must verify HTML, client navigation, locale behavior, and reading without JavaScript.

Learning state uses `lac:v1:{courseId}:achievement:{achievementId}` records with an `unlockedAt` timestamp. The content scanner extracts static Achievement/AchievementOption declarations into article definitions. Publication validation rejects duplicate course achievement IDs and translated option/answer drift. Course manifests collect source-language achievement IDs, lesson ownership, display titles, and exercise anchor URLs; translated exercises supply localized titles and targets, with original-article fallback when an exercise is missing; all translations receive the same inventory, including when a translated exercise is omitted. The server MDX registry binds the article definitions to the generic client challenge. LearningStorage accepts only manifest-registered IDs. The `generation-vs-verification` achievement belongs to `llm-101:how-language-models-are-trained-part-1`; stable IDs share counts across translations. Learning records use the `llm-101` course namespace. Recent visits retain `lac:v1:{courseId}:last` with `lessonId` and `visitedAt`. Legacy `lesson:` completion records remain untouched and do not count. AchievementProvider lives in the locale layout, keeps one LearningStorage adapter per published course, and synchronizes all registered course records across tabs. Its inventory selects one translation per course, preferring the current language and otherwise using the original. LearningProvider binds the current course to that shared state for exercises and recent visits. Existing course-scoped storage keys remain unchanged, while in-memory records survive client navigation between courses when storage is blocked. Answer feedback is local presentation state: an incorrect answer keeps retry enabled, while a correct answer immediately records the unlock and displays the earned title, takeaway, and retry action; explanations remain in incorrect feedback and the no-JavaScript fallback. An explicit local retry mode allows another attempt from the earned card without changing the saved unlock, its timestamp, or course statistics. Reloaded or remotely restored unlocks render the earned card directly. The adapter protects corrupt records and falls back to page memory when storage fails. Visiting never unlocks an achievement; the sidebar highlights the current route and its footer opens the global achievement gallery from the medal ring and total earned count. The gallery lists every published course’s medals once per course/achievement pair and computes one global progress value. It uses the shared Radix dialog, a four-column desktop grid (two columns on narrow screens), straight borders, offset shadows, and live aggregate progress. Each medal has an overlaid lesson link revealed on hover or keyboard focus and always shown on touch devices. Links target stable achievement anchors and dismiss both the gallery and the mobile sidebar. The original article remains reachable when an exercise is unavailable in the selected language. Its adjacent language dropdown reuses the same destination logic as the native header language switcher.

The earned card places two shared outlined Buttons with matching borders and padding below its takeaway: Try again with the localized ArrowCounterClockwise icon and View all achievements with a Medal icon. AchievementGallery accepts a custom trigger, so both the card action and sidebar summary reuse the same global gallery and Radix focus restoration. The achievement component starts celebrations only after an explicit local correct answer. Its adjacent confetti module owns a temporary, aria-hidden, pointer-transparent viewport layer and native transform/opacity animations from both bottom corners. A cleanup function cancels the burst on retry or unmount; animation completion and reduced-motion changes also dispose the layer. Restored learning state never starts a burst. No animation dependency, MDX field, or persistence interface is added.

Search loads the active language's static index. Results belong to a specific query; pending queries cannot activate older results. The sidebar owns collapse and mobile navigation state, while lesson bodies remain server-rendered.

The shared ModuleTree renders a course-overview link from the current manifest above its modules, derives numbering from groupModules, and aligns module and lesson number columns using the same rem-based arrow spacing without narrowing active backgrounds. Lesson titles retain their indentation, and the shared rounded-md token keeps the achievement and footer-control hover backgrounds consistent. Interactive and native no-JavaScript navigation reuse the same tree. The course sidebar uses the same 961px desktop boundary in CSS and its media-query subscription. On narrower viewports, a compact sticky brand header provides an icon-based course-navigation trigger, with a visible text label where space permits. Only that control receives the focus outline. The mobile sheet fits the dynamic viewport and leaves a 1rem outside edge; its header/footer do not shrink and its lesson list scrolls independently. Media-query changes clear mobile-open state while retaining the separate persisted desktop collapse state. Following a navigation link also clears mobile state, including when the destination is the current lesson. Closing restores the previous visible control without scrolling the document. Without JavaScript, the same header provides native details navigation with static module headings and author/language links; no fallback navigation is inserted beside or below the lesson.

## Build and verification

Normal builds read `content/`, generate `.source/`, and write `.next`. `CONTENT_TEST=1` reads `tests/fixtures/`, generates `.source-test/`, and writes `.next-test`. `config/content-mode.mjs` keeps these paths together and rejects fixture mode on Vercel. Generated import aliases select the same mode for the catalog, route snapshot, and compiled MDX in both Turbopack and Webpack. TypeScript can inspect either generated tree; application builds never fall back between modes.

`pnpm check` verifies structure, documentation links, lint, types, content, dictionary parity, and existing unit checks. `pnpm audit --prod` checks current production dependency advisories; CI rejects high and critical findings. Run E2E only for affected modules during development. CI and release checks run the full public and fixture matrices in Chromium, Firefox, and WebKit.

Generated evidence stays in Git-ignored `.artifacts/`: browser reports and attachments in `e2e/{public,fixtures}`, structure checks and local reviews in `review`, Lighthouse output in `performance`, and optional screenshot references in `visual`. The performance script discovers available pages from a running server's sitemap. For one-page checks, set `PERFORMANCE_PATH` and `PERFORMANCE_RUNS`; local measurements are not field performance data.
