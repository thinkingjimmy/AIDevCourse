# Architecture

The site uses Next.js App Router, React, Fumadocs MDX, next-intl, and Tailwind CSS. Exact versions live in `package.json` and `pnpm-lock.yaml`. Use Node 22.17.0 or a later 22.x patch, or Node 24.x, and pnpm 10.30.3. CI and production remain on Node 22.x. Reading needs no database or external content service; optional external link previews read the destination's public metadata.

## Module boundaries

| Module | Responsibility |
| --- | --- |
| [app](../src/app/) | Compose routes, static metadata, locale providers, and public search responses. |
| [components](../src/components/) | Keep course, layout, MDX, progress, search, and illustration behavior together by purpose. |
| [content](../src/lib/content/) | Scan, validate, compile, and query the published catalog. |
| [i18n](../src/lib/i18n/) | Supported languages, preference negotiation, dictionaries, and URL parsing. |
| [lib](../src/lib/) | Small shared progress, search, metadata, redirect, and utility modules. |
| [styles](../src/styles/) | Shared Tailwind theme, typography scale, and @apply defaults for documents, Markdown, and SVG. |

Routes compose components and query server content. Browser components receive serializable catalog data; they must not import the filesystem scanner or compiled server modules. Course-only controls stay in `components/course`. Shared UI primitives stay in `components/ui`; dialogs share `ui/overlays`. The two hero illustrations share an animation driver while retaining their own markup and timing.

`components/mdx/notes` shares FramedNote between JimmyNote author commentary and KeyTakeaway memory notes. The frame owns the border, shadow, top-edge signature position, accessible note label, and rich Markdown body. KeyTakeaway resolves its fixed label through next-intl on the server. The MDX registry and validator expose it as a standalone nonempty block without attributes; both notes render without browser JavaScript.

`components/mdx/llm-training` owns independent one-round and multi-round demonstrations of 今天雨天，出门记得带…, with 伞, 雨衣, and 帽子 as candidates. Shared model data owns the input, target, candidate order, and probabilities. The single-round demo reuses FormulaTrainingModel across steps 00–03: parameter initialization, prediction, comparison, and adjustment. Initialization hides inputs and predictions; the original model stays mounted, and the updated model appears only in step 03. Candidate scores and softmax probabilities are calculated from fixed a/b coefficients and x = 1. The multi-round demo derives its first two probability distributions from those same formula models, then shows further illustrative training checkpoints. Each client component keeps independent bounded state. The MDX registry exposes both demos as parameterless, childless standalone blocks. Static no-JavaScript alternatives preserve all steps without changing achievements or browser storage.

`components/mdx/pretraining` owns the three-tab LLMPretrainingOverview used in the training lesson. Radix Tabs provides keyboard navigation and selected-panel semantics. Its diagrams reuse TrainingFrame and the tokenization module's shared text, token IDs, and TokenPairs renderer. PredictionCycle measures its nodes with ResizeObserver to connect parameter adjustment back to prediction in horizontal and vertical layouts; unmounting disconnects the observer. The MDX registry and validator expose a parameterless standalone block. A static fallback preserves all three stages without JavaScript or learning-storage changes.

The MDX anchor registry uses `components/mdx/link-preview` for Radix hover/focus cards and native navigation. `/api/link-preview` delegates to `lib/link-preview`: local pages read catalog summaries, while outbound requests require an exact published HTTPS link. The network boundary checks and pins public IPv4 DNS on every redirect, reads at most 256 KiB with a 4.5-second deadline, and returns text metadata with an optional public HTTPS cover. When the system resolver returns only proxy-generated addresses in 198.18.0.0/15, it queries Cloudflare's fixed HTTPS DNS endpoint for the hostname and applies the same public-IP checks to those answers. The hostname alone is sent to the resolver; private and reserved destinations remain blocked. Successful external metadata is cached for one hour; the browser shares bounded requests and uses short-lived failure entries. Unavailable remote metadata returns 204 with a short cache lifetime, while unsupported destinations retain 404. Reading and navigation work independently of remote metadata.

Local development uses `next dev --webpack` to avoid Turbopack CSS hot-replacement failures. Its in-memory Webpack cache avoids unsupported filesystem-cache tracing of dynamic imports in MDX and next-intl dependencies; production cache settings are unchanged. Its regression check starts a separate application copy, changes real CSS, verifies hot replacement without a page reload, and records browser errors and stylesheet responses.

Avoid single-file directory layers and unused generic APIs. A directory is useful when it owns a coherent group of files. Source files stay within 800 lines; each directory has at most eight maintained files.

`components/mdx/chat-sequence` owns ChatMessageSequence, the standalone request/response demonstration in how-ai-chat-works. The model defines two attempts and simplified request/response JSON. Playback advances discrete steps once, with visibility-aware timers and cleanup. A layout hook measures real message lines and anchors the current floating bubble and pointer to their midpoint; ResizeObserver handles content and container changes. Phosphor icons and semantic format colors distinguish invalid and valid requests. MDX validation rejects attributes, children, and inline use. No-JavaScript readers receive both complete static sequences; no model calls or learning-storage writes occur.

## Styling

Tailwind is the sole application styling system. Components use utilities; native document rules and generated Markdown/SVG selectors use @apply. The shared [typography tokens](../src/styles/typography.css) defines rem-based sizes, unitless leading, font weights, and responsive title roles. Public pages and design previews import the same theme. The cn helper registers custom typography names with tailwind-merge so overrides do not remove font sizes when applying colors. Structure validation rejects numeric arbitrary typography values and literal CSS typography declarations.

Lesson pages preserve a 42.5rem article column. At a reading-container width of 64rem, lessons with headings use a centered group capped at 65.5rem with a 21rem right rail and a 2rem gap. The rail contains native heading links and the server-rendered `components/course/author-card`, with bounded scrolling for short viewports. Below that threshold, hide the entire rail without adding an author card or an empty row below the article. Lessons without headings omit the rail. The card reuses Card, Button, the existing avatar, the shared radius token, and the product's offset shadow; it needs no client state. Public author destinations and the optional WeChat QR image live in `lib/site-config`. Unconfigured Xiaohongshu and QR entries remain explicit, non-navigating placeholders. Five dictionaries own the card's visible and accessible labels.

`components/course/outline` owns the lesson outline's client enhancement. Its active-heading hook samples actual heading positions at most once per animation frame on passive page scroll, viewport changes, fragment navigation, font loading, and article resizing. The reading line follows the heading's existing scroll margin. The last section remains selectable near the article's end. Active links expose `aria-current="location"`, a dark left indicator, and medium-weight text. Keeping the current link visible scrolls only the right rail; manual reading never rewrites the URL or browser history. Without JavaScript the server-rendered anchors remain available without a misleading static active state.

## Content pipeline

1. Authors edit `content/{lang}` and explicitly order files in `meta.json`. Course-root index files infer course kind; other article paths infer lesson kind. Authors provide stable lesson IDs, titles, descriptions, and course ownership, without duration, classification, or revision fields.
2. `scan.ts`, `schema.ts`, `mdx.ts`, and `validate.ts` check identity, metadata, ordering, the safe MDX subset, image dimensions, and rendered link destinations. Validation uses the same Fumadocs YAML parser as compilation.
3. The Fumadocs configuration writes compiled modules and a catalog into `.source/` for public content or `.source-test/` for fixtures.
4. `source.ts` exposes server queries. Development reads and validates current content once per request through React cache; production reads the generated catalog. `manifest.ts` and `model.ts` define serializable courses, lessons, translation maps, and rendered anchors.
5. Routes, metadata, sitemap, and the search API consume the same published catalog.

The course overview renders frontmatter and the syllabus anchor `course-catalog`. Lesson pages render their body headings. Link validation and language switching use these rendered anchors. Course/module folders determine organization; public lesson URLs omit the module folder.

Body edits and achievement declarations support development hot reload. Current validated definitions and course achievement inventories come from the same request snapshot, so adding an achievement cannot leave its MDX binding on the startup catalog. Restart after frontmatter, filename, or ordering changes to refresh compiled routes. Do not edit generated files by hand.

## Routing and client state

`src/lib/i18n/routing.ts` owns canonical paths: English has no prefix; the other languages retain one. The catalog, UI, metadata, sitemap, search filtering, and link validation share this rule. `src/proxy.ts` negotiates only `/`, preserves explicit native homepage language choices, rewrites canonical English URLs to internal `/en` App Router routes, and validates published paths. Direct `/en` URLs redirect permanently to their canonical address; article and About URLs never negotiate language. Missing pages use static unavailable documents with a 404 status. Root and locale not-found adapters and proxy documents all use the single server-rendered MissingPage renderer, which owns localized copy and native recovery links. The locale layout also passes MissingPage as the SiteFrame recovery slot. SiteFrame exposes it through useErrorPage to the client runtime-error adapter and restores the header/footer for failed lesson routes; other routes reuse their existing frame. Runtime failures retain their actual error semantics. Native recovery navigation reloads the destination and clears failed client state. The root, locale, and design documents share pinned Fontsource WOFF2 assets and font variables from `src/styles/fonts.css`, with unicode-range CJK subsets loaded only when used. Font compilation has no Google network dependency; 404 titles and decorative numerals use regular-weight Geist Pixel with locale-specific glyph fallbacks, and both recovery buttons reuse the homepage Hero's action-raised variant. Framework route adapters remain separate from this one presentation. Changes to the routing adapter must verify HTML, client navigation, locale behavior, and reading without JavaScript.

Learning state uses `lac:v1:{courseId}:achievement:{achievementId}` records with an `unlockedAt` timestamp. The content scanner extracts static Achievement/AchievementOption declarations into article definitions. Publication validation rejects duplicate course achievement IDs and translated option/answer drift. Course manifests collect source-language achievement IDs, lesson ownership, display titles, and exercise anchor URLs; translated exercises supply localized titles and targets, with original-article fallback when an exercise is missing; all translations receive the same inventory, including when a translated exercise is omitted. The server MDX registry binds the article definitions to the generic client challenge. LearningStorage accepts only manifest-registered IDs. The `generation-vs-verification` achievement belongs to `llm-101:how-language-models-are-trained-part-1`; stable IDs share counts across translations. Learning records use the `llm-101` course namespace. Recent visits retain `lac:v1:{courseId}:last` with `lessonId` and `visitedAt`. Legacy `lesson:` completion records remain untouched and do not count. AchievementProvider lives in the locale layout, keeps one LearningStorage adapter per published course, and synchronizes all registered course records across tabs. Its inventory selects one translation per course, preferring the current language and otherwise using the original. LearningProvider binds the current course to that shared state for exercises and recent visits. Existing course-scoped storage keys remain unchanged, while in-memory records survive client navigation between courses when storage is blocked. Answer feedback is local presentation state: an incorrect answer keeps retry enabled, while a correct answer immediately records the unlock and displays the earned title, takeaway, and retry action; explanations remain in incorrect feedback and the no-JavaScript fallback. An explicit local retry mode allows another attempt from the earned card without changing the saved unlock, its timestamp, or course statistics. Reloaded or remotely restored unlocks render the earned card directly. The adapter protects corrupt records and falls back to page memory when storage fails. Visiting never unlocks an achievement; the sidebar highlights the current route and its footer opens the global achievement gallery from the medal ring and total earned count. The gallery lists every published course’s medals once per course/achievement pair and computes one global progress value. It uses the shared Radix dialog, a four-column desktop grid (two columns on narrow screens), straight borders, offset shadows, and live aggregate progress. Each medal has an overlaid lesson link revealed on hover or keyboard focus and always shown on touch devices. Links target stable achievement anchors and dismiss both the gallery and the mobile sidebar. The original article remains reachable when an exercise is unavailable in the selected language. Its More dropdown reuses LanguageSubmenu and the same links as the native header language switcher.

The earned-card header uses the shared ghost/icon-touch Button and a localized ArrowCounterClockwise retry icon. The achievement component starts celebrations only after an explicit local correct answer. Its adjacent confetti module owns a temporary, aria-hidden, pointer-transparent viewport layer and native transform/opacity animations from both bottom corners. A cleanup function cancels the burst on retry or unmount; animation completion and reduced-motion changes also dispose the layer. Restored learning state never starts a burst. No animation dependency, MDX field, or persistence interface is added.

Search loads the active language's static index. Results belong to a specific query; pending queries cannot activate older results. The sidebar owns collapse and mobile navigation state, while lesson bodies remain server-rendered.

The shared ModuleTree renders a course-overview link from the current manifest above its modules, derives numbering from groupModules, and aligns module and lesson number columns using the same rem-based arrow spacing without narrowing active backgrounds. Lesson titles retain their indentation, and the shared rounded-md token keeps the achievement and More hover backgrounds consistent. Interactive and native no-JavaScript navigation reuse the same tree. The course sidebar uses the same 961px desktop boundary in CSS and its media-query subscription. On narrower viewports, a compact sticky brand header provides an icon-based course-navigation trigger, with a visible text label where space permits. Only that control receives the focus outline. The mobile sheet fits the dynamic viewport and leaves a 1rem outside edge; its header/footer do not shrink and its lesson list scrolls independently. Media-query changes clear mobile-open state while retaining the separate persisted desktop collapse state. Following a navigation link also clears mobile state, including when the destination is the current lesson. Closing restores the previous visible control without scrolling the document. Without JavaScript, the same header provides native details navigation with static module headings and About/language links; no fallback navigation is inserted beside or below the lesson.

## Build and verification

Normal builds read `content/`, generate `.source/`, and write `.next`. `CONTENT_TEST=1` reads `tests/fixtures/`, generates `.source-test/`, and writes `.next-test`. `config/content-mode.mjs` keeps these paths together and rejects fixture mode on Vercel. Generated import aliases select the same mode for the catalog, route snapshot, and compiled MDX in both Turbopack and Webpack. TypeScript can inspect either generated tree; application builds never fall back between modes.

`pnpm check` verifies structure, documentation links, lint, types, content, dictionary parity, and existing unit checks. `pnpm audit --prod` checks current production dependency advisories; CI rejects high and critical findings. Run E2E only for affected modules during development. CI and release checks run the full public and fixture matrices in Chromium, Firefox, and WebKit.

Generated evidence stays in Git-ignored `.artifacts/`: browser reports and attachments in `e2e/{public,fixtures}`, structure checks and local reviews in `review`, Lighthouse output in `performance`, and optional screenshot references in `visual`. The performance script discovers available pages from a running server's sitemap. For one-page checks, set `PERFORMANCE_PATH` and `PERFORMANCE_RUNS`; local measurements are not field performance data.
