# Current product requirements

AIDevCourse is a multilingual site for learning from local Markdown and MDX courses. Reading must work without an account or a model API key. LLM 101 has introductions in five languages, Chinese lessons about LLM generation, input quality, sampling, tokens, probability calculation, and model training, and welcome placeholders in the other languages. The Chinese lessons form three modules: 大语言模型的工作原理 (four lessons), 模型的训练与能力 (pretraining, thinking, multimodal inputs, and model selection), and AI 应用的工作原理 (AI Chat). Lesson URLs and progress identities stay stable when files move. LLM 101 remains a beginner course without post-training tutorials; practical Chat use belongs with the corresponding application concepts. Agent 101 is proposed as a separate intermediate course and is not published. Engineering fixtures remain separate from published courses.

## Routes and publication

| Route | Required behavior |
| --- | --- |
| `/` | Detect saved/browser language. Serve English at this URL, or redirect to another language with a private, non-cacheable 307 response. |
| `/` or `/{lang}` | Show the current language's courses. The start-learning action (马上学习 in Chinese) opens LLM 101's first published lesson. Keep a useful empty state when no courses exist. |
| `/courses/{course}` or `/{lang}/courses/{course}` | Render course metadata, available modules, and the syllabus. |
| `/courses/{course}/{lesson}` or `/{lang}/courses/{course}/{lesson}` | Render a published lesson, its local headings, recent-visit recording, inline achievements where authored, and adjacent lessons. |
| `/about` or `/{lang}/about` | Explain the site, language preference, and local learning storage. |
| `/api/search/{lang}` | Serve the same build's public, single-language content index. |

Supported languages are `en`, `zh`, `ja`, `fr`, and `es`. English public URLs have no locale prefix; the other four languages retain theirs. Only `/` uses a valid preference cookie, then `Accept-Language`, then `en`. An explicit `?lang=en` homepage choice supports native language links without JavaScript and saves the preference. Other canonical URLs always use their declared language. Former `/en` paths redirect permanently to the equivalent prefix-free URL. Unknown routes and missing translations return HTTP 404 with working recovery links. All 404 entries use the same two-column page with a direct localized Page not found title, regular-weight Geist Pixel title/numeral typography with CJK fallbacks, and square raised buttons matching the homepage Hero. Runtime failures inside language routes use that same complete 404 interface, including the header, footer, course/home actions, and language links. They keep their actual error semantics; displaying 404 does not turn a runtime failure into an HTTP 404 response. Recovery links reload their destination to clear failed client state. There is no separate page-loading-error screen or retry action. `/courses` and `/{lang}/courses` are not pages; the language homepage lists courses.

Content in `content/` is public. Every course and module declares order through `meta.json`. Course introductions do not count as lessons. Course overviews use frontmatter and the generated syllabus; their MDX bodies are not rendered. Lesson URLs omit module directories.

## Language and identity

- Use the exact product name `AIDevCourse` in every language. Use the supplied letter-to-shape SVG wordmark in site headers and course sidebars, cropped to the lettering with a transparent background. Browser icons retain the terminal-prompt mark. Keep brand assets in `public/images/brand/`.
- Identify languages by their names in the switcher; flag decorations cannot replace them. Localize controls, errors, empty states, and accessible names.
- Keep `courseId`, `lessonId`, and `sourceLocale` stable across translations and URL changes.
- Link to the requested translation when available. Otherwise, explain the missing translation and link to its course overview or language homepage.
- Preserve a URL fragment only when the destination renders that anchor. Do not substitute another language's body or fabricate a translation.
- Infer course/lesson kind from the file path. Articles require only courseId, lessonId, title, and description. Do not maintain reading duration, lesson classification, verification metadata, revision numbers, or stale-translation notices.

Preserve native navigation and readable content without JavaScript.

On wide lesson pages, give the right-hand outline 21rem without reducing the article's 42.5rem reading width. Show the two-column layout only when the reading container is at least 64rem wide. Keep complete heading text and native anchor navigation. Place an author card below the outline, using Jimmy's existing avatar, the shared 3px radius, a 4px right/down hard shadow, a project Star link, X at `https://x.com/thinkingjimmy`, and a lightweight book icon for Xiaohongshu. Preserve keyboard access, short-viewport reachability, enlarged text, five-language labels, and no-JavaScript reading.

The right outline highlights the current section while scrolling, following a native anchor, opening a fragment URL, and navigating browser history. Keep the previous section active until the next heading reaches the reading line, and activate the last section at the article's end. Accommodate font and content layout changes. Use the supported Markdown and MDX subset described in [authoring.md](./authoring.md). Images need meaningful localized alt text and known dimensions. The build must reject unsafe MDX, invalid metadata, duplicate identities or paths, broken local links, and missing rendered anchors.

Authors use a standalone, nonempty `<KeyTakeaway>` block for conclusions readers should remember. Reuse JimmyNote's quotation border, offset shadow, full-width body, and top-edge label layout. Fetch metadata only after opening and reuse requests. Local published articles use catalog metadata; external HTTPS previews are limited to published outbound links, public IP destinations, bounded responses, checked redirects, and a short deadline. Loading and unavailable states are localized in five languages. Missing metadata or images must preserve native navigation. Touch links open on the first tap. Hash, email, and download links and no-JavaScript reading retain their native behavior.

Proxy-generated DNS addresses may use a public HTTPS resolver fallback, with the same public-IP checks on the real answers. Pages that deny metadata reads or have no usable metadata produce a normal empty-204 preview response instead of a server error. Local development must apply CSS edits without missing stylesheet chunks, unhandled browser rejections, or a full document reload.

## Scope and acceptance

The probability-calculation lesson uses a static TokenProbabilityDiagram with the shared quote frame and neutral input and sampling surfaces. Show 今天下雨，出门记得带… as input, a downward connected computation network, multiple scores aligned above the named candidates 伞, 雨衣, 帽子, and an ellipsis for other candidates. Join all candidate lanes into one sampling step labeled 按采样策略选择一个 Token ID and show 伞 directly as its example result. Score numbers identify illustrative columns; do not invent numeric vocabulary IDs. Probability conversion stays in the preceding article explanation rather than a separate diagram stage. No visible overall heading, footer, animation, controls, network requests, or client state is required. Render completely on the server, support narrow/enlarged/no-JavaScript reading, and retain screenshot/JSON acceptance evidence. MDX accepts only a standalone declaration without attributes or children.

The Chinese model-training lesson includes two independent prediction-training demos using 今天雨天，出门记得带… with candidates 伞, 雨衣, and 帽子. The one-round demo has four numbered stages: 00 initialization, 01 prediction, 02 comparison, and 03 parameter adjustment. Initialization shows only candidate-specific a/b values; hide input, scores, probabilities, and source answers until their corresponding steps. Prediction uses fixed illustrative x = 1 for rain and preserves those initialized coefficients. Comparison reveals 伞 beside the input without changing model values. Adjustment retains the unchanged original model and adds an updated model on the right, stacking on narrow screens. For 伞, a/b change from 0.50/1.10 to 0.60/1.20 and its score changes from 1.60 to 1.80. Compute actual softmax distributions from the illustrative candidate scores: 25/40/35% before and 45/30/25% after. Show scores to two decimal places and probabilities as whole percentages. Preserve the original model DOM and data, support returning to initialization, and keep step status announcements screen-reader-only. Step 02 adds one handwritten Chinese note with a hand-drawn arrow near the umbrella probability: explain that the source answer is 伞 but the model gives it only 25%, so training should raise its probability. Show the note only during comparison, use open-licensed local WOFF2 glyphs without a network font dependency, and reflow the note above the probability bars on narrow or enlarged layouts without covering the calculations. The multi-round demo shares the same input, candidates, target, and first two distributions, then raises the umbrella probability through 60% and 72%; stop after three rounds and replay independently. Both reuse the quote frame and Button, omit visible headings/source blocks/footnotes, and keep state out of learning progress. Require keyboard operation, screen-reader feedback, narrow/enlarged-text reading, reduced-motion support, static no-JavaScript reading, and screenshot/JSON evidence for initialization, candidate consistency, visible arithmetic, and probability checks. MDX accepts only standalone declarations without attributes or children.

The current scope is course discovery, reading, translation navigation, local achievements, recent visits, and search. Accounts, payments, cloud sync, model execution, scored exams or a general quiz engine, embedded video, dark mode, and learning-record import/export have no active implementation requirement. Add an interactive teaching component only when a real article requires it; first define its input, states, failure behavior, and acceptance cases.

Use [architecture.md](./architecture.md) for code boundaries and [deployment.md](./deployment.md) for release gates. Changes require source checks, a production build where applicable, and E2E checks for affected behavior. A release also requires both complete browser matrices, reviewed published content and translations, real-device/input-method checks, and deployment verification. Local automated results do not establish that these release gates are complete.
